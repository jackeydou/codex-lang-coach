# Dashboard 复习排序验证记录

日期：2026-10-03。实现范围：插件 Dashboard 和本地独立网页。所有笔记写入都使用临时测试数据库；未改动真实学习进度。

## 自动检查

- `pnpm check`：所有 workspace 类型检查通过。
- `pnpm test`：全套通过；后续补充事务回滚测试后，Core 重跑通过。共 45 项测试：Core 20、Dashboard 15、MCP 4、本地 HTTP 2、Worker 4。
- `pnpm build:plugin`：独立网页、MCP App 单文件 HTML、本地服务和发布包构建通过。Worker build 只执行 dry-run，没有部署。
- `node scripts/test-codex-ui.mjs --review-only`：使用 Codex CLI 0.154.0 的实际 app-server 协议验证编译后的插件：UI 入口发现、HTML resource 读取、设置更新、笔记保存、复习写入、相同请求去重、复习排序读取及删除均通过。

协议测试不证明原生 Codex UI 渲染成功。默认脚本还要求已安装开发插件的 prompt hook；当前环境未启用该 hook，因此默认检查在该断言处停止。新增的 `--review-only` 明确跳过开发 hook 断言，报告 `developmentHooksVerified: false`，保留编译产物的 UI/MCP 检查。未修改安装插件、hook 配置或真实数据库。

## 已覆盖的业务边界

- 新卡与迁移后的历史卡初始阶段为 0；读取和翻页不推进。
- 复习在准确到期时推进；间隔为 1、3、7、14、30、60 天，阶段封顶后计数仍增加。
- 逾期复习从实际完成时间起算，不跳级。
- 请求去重、同 ID 不同参数、未到期、旧版本、无效输入与已不存在笔记均得到正确处理。
- 写事件失败时整笔复习事务回滚，可用原请求 ID 重试。
- SQLite 两个连接共享复习状态及分页会话；重开存储后状态持久化。
- 复习不会修改笔记的上传版本；普通笔记列表和上传快照不携带复习字段。
- 删除笔记级联清理状态与事件。
- 63 张笔记中更早创建的到期卡排在第一页；固定卡组在复习、删除、新增和跨越到期时间后仍按快照分页。
- 非法、混用和过期游标得到明确错误；新建会话清理过期快照。
- 前端合并较晚到达的分页响应时保留更新版本的复习状态；相同结果不重复调整计数。
- HTTP 与 MCP 都保留可识别的错误码及冲突时的最新复习状态。
